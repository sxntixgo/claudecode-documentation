\chapter{MCP Servers}
\label{ch:mcp-servers}

\index{MCP!overview}

Claude Code's built-in tools — reading files, writing code, executing shell
commands — cover most of your local development needs. The Model Context
Protocol (MCP) extends those capabilities to the outside world: live databases,
issue trackers, cloud APIs, monitoring dashboards, and any other service that
matters to your workflow.

\section{What Is the Model Context Protocol?}
\label{sec:mcp-what}

\textbf{MCP} is an open standard published by Anthropic that defines how AI
assistants communicate with external tools and data sources. It uses
\textbf{JSON-RPC 2.0} as its wire protocol and supports three transport
mechanisms:

\begin{table}[ht]
\centering
\caption{MCP transport options (verified 2026-05-27)}
\label{tab:mcp-transports}
\begin{tabularx}{\textwidth}{llX}
\toprule
\textbf{Transport} & \textbf{Status} & \textbf{Use case} \\
\midrule
\texttt{http} (streamable HTTP) & Recommended & Cloud-based services; remote servers \\
\texttt{stdio}                  & Stable       & Local processes; scripts; direct system access \\
\texttt{sse} (Server-Sent Events) & Deprecated & Legacy servers only; prefer HTTP \\
\bottomrule
\end{tabularx}
\end{table}

An MCP server exposes:
\begin{itemize}
  \item \textbf{Tools} — functions Claude can call
        (e.g.\ \texttt{create\_issue}, \texttt{run\_query});
  \item \textbf{Resources} — data Claude can fetch and reference with
        \texttt{@server:protocol://path} syntax;
  \item \textbf{Prompts} — server-provided prompt templates that appear as
        \texttt{/mcp\_\_servername\_\_promptname} slash commands.
\end{itemize}

\section{How MCP Works}
\label{sec:mcp-how}

\begin{enumerate}
  \item You ask Claude in plain language:
        ``Review PR \#456 and suggest improvements.''
  \item Claude identifies which registered MCP tool can satisfy the request.
  \item Claude Code sends a JSON-RPC request to the server.
  \item The server executes the tool (e.g.\ calls the GitHub API) and returns
        a structured result.
  \item Claude interprets the result and presents it to you.
\end{enumerate}

This happens automatically — no custom scripting required on your part.

\subsection{Request and Response Example}

\begin{lstlisting}[language=json,caption={MCP tool call (JSON-RPC 2.0)}]
{
  "jsonrpc": "2.0",
  "method": "tools/call",
  "params": {
    "name": "create_issue",
    "arguments": {
      "repo": "owner/repo",
      "title": "Bug: login fails",
      "body": "Reproducible with credentials X"
    }
  },
  "id": 1
}
\end{lstlisting}

\begin{lstlisting}[language=json,caption={MCP response}]
{
  "jsonrpc": "2.0",
  "result": { "issue_number": 123,
              "url": "https://github.com/owner/repo/issues/123" },
  "id": 1
}
\end{lstlisting}

\section{Installing MCP Servers}
\label{sec:mcp-install}

\index{MCP!installation}

Claude Code supports three installation methods.

\subsection{Method 1: HTTP Servers (Recommended)}

Remote HTTP servers are the simplest option for cloud-based services. Many
providers now publish hosted MCP endpoints directly:

\begin{lstlisting}[language=bash,caption={Adding an HTTP MCP server}]
# Basic form
claude mcp add --transport http <name> <url>

# Example: GitHub (via GitHub Copilot MCP endpoint)
claude mcp add --transport http github \
  https://api.githubcopilot.com/mcp/ \
  --header "Authorization: Bearer YOUR_GITHUB_PAT"

# Example: Sentry
claude mcp add --transport http sentry https://mcp.sentry.dev/mcp
\end{lstlisting}

After adding a remote server that uses OAuth, run \texttt{/mcp} inside a
Claude Code session to complete the browser authentication flow.

\subsection{Method 2: Local Stdio Servers}

Stdio servers run as local processes and are ideal for custom scripts or tools
that need direct file-system access:

\begin{lstlisting}[language=bash,caption={Adding a local stdio MCP server}]
# PostgreSQL database connector
claude mcp add --transport stdio db -- npx -y @bytebase/dbhub \
  --dsn "postgresql://readonly:pass@localhost:5432/mydb"

# Custom Python script
claude mcp add --transport stdio my-api -- python3 /path/to/server.py
\end{lstlisting}

\begin{notebox}
Claude Code sets \texttt{CLAUDE\_PROJECT\_DIR} in the spawned server's
environment so the server can resolve project-relative paths without depending
on the working directory.
\end{notebox}

\subsection{Method 3: Import from Claude Desktop}

If you have servers already configured in the Claude Desktop app, import them
in one step:

\begin{lstlisting}[language=bash,caption={Import from Claude Desktop (macOS/WSL)}]
claude mcp add-from-claude-desktop
\end{lstlisting}

\subsection{Managing Servers}

\begin{lstlisting}[language=bash,caption={Server management commands}]
claude mcp list          # list all configured servers
claude mcp get github    # show details for one server
claude mcp remove github # remove a server
# Within a session:
/mcp                     # interactive panel (shows tool count, auth status)
\end{lstlisting}

\section{Configuration and Scopes}
\label{sec:mcp-scopes}

\index{MCP!configuration scopes}

Every MCP server has a \emph{scope} that controls where it loads and whether
it is shared with teammates.

\begin{table}[ht]
\centering
\caption{MCP server configuration scopes}
\label{tab:mcp-scopes}
\begin{tabularx}{\textwidth}{lllX}
\toprule
\textbf{Scope} & \textbf{Stored in} & \textbf{Team-shared?} & \textbf{Use for} \\
\midrule
\texttt{local} (default) & \texttt{\textasciitilde/.claude.json}
  & No & Personal dev servers, secrets \\
\texttt{project}         & \texttt{.mcp.json} (project root)
  & Yes & Team-wide integrations \\
\texttt{user}            & \texttt{\textasciitilde/.claude.json}
  & No & Personal servers across all projects \\
\bottomrule
\end{tabularx}
\end{table}

\begin{lstlisting}[language=bash,caption={Adding a project-scoped server}]
# Written to .mcp.json at project root — commit this file to share with team
claude mcp add --transport http paypal --scope project \
  https://mcp.paypal.com/mcp
\end{lstlisting}

\begin{lstlisting}[language=json,caption={Resulting \texttt{.mcp.json} (safe to commit — no secrets)}]
{
  "mcpServers": {
    "paypal": {
      "type": "http",
      "url": "https://mcp.paypal.com/mcp"
    }
  }
}
\end{lstlisting}

Environment variables expand inside \texttt{.mcp.json} using
\texttt{\$\{VAR\}} or \texttt{\$\{VAR:-default\}} syntax, so API keys stay
out of version control:

\begin{lstlisting}[language=json,caption={Environment variable expansion in \texttt{.mcp.json}}]
{
  "mcpServers": {
    "internal-api": {
      "type": "http",
      "url": "${API_BASE_URL:-https://api.example.com}/mcp",
      "headers": { "Authorization": "Bearer ${API_KEY}" }
    }
  }
}
\end{lstlisting}

\section{Creating Custom MCP Servers}
\label{sec:mcp-custom}

\index{MCP!custom servers}

When no existing server fits your needs, build one. The fastest route is to
have Claude scaffold it for you:

\begin{lstlisting}[language=bash,caption={Scaffolding a new MCP server with the dev plugin}]
/plugin install mcp-server-dev@claude-plugins-official
/mcp-server-dev:build-mcp-server
\end{lstlisting}

Claude will ask about your use case and generate a starter project for either
a remote HTTP server or a local stdio server.

\subsection{Anatomy of a Minimal Stdio Server (TypeScript)}

\begin{lstlisting}[language=Java,caption={Minimal MCP server skeleton (TypeScript)}]
import { Server } from '@modelcontextprotocol/sdk/server/index.js';
import { StdioServerTransport } from
  '@modelcontextprotocol/sdk/server/stdio.js';

const server = new Server(
  { name: 'my-server', version: '1.0.0' },
  { capabilities: { tools: {} } }
);

server.setRequestHandler('tools/list', async () => ({
  tools: [{
    name: 'greet',
    description: 'Return a greeting',
    inputSchema: {
      type: 'object',
      properties: { name: { type: 'string' } },
      required: ['name']
    }
  }]
}));

server.setRequestHandler('tools/call', async (req) => {
  const { name } = req.params.arguments as { name: string };
  return { content: [{ type: 'text', text: `Hello, ${name}!` }] };
});

await server.connect(new StdioServerTransport());
\end{lstlisting}

\section{MCP Tool Search}
\label{sec:mcp-tool-search}

\index{MCP!tool search}

By default, every connected MCP server's tool definitions load into context
at session start, which is expensive once you have more than a handful of
servers. \textbf{Tool Search} defers them: only tool \emph{names} load up
front, and Claude searches for relevant tools on demand. Tool Search is on
by default on first-party API endpoints; control it with the
\texttt{ENABLE\_TOOL\_SEARCH} environment variable:

\begin{table}[ht]
\centering
\caption{\texttt{ENABLE\_TOOL\_SEARCH} values}
\label{tab:tool-search}
\begin{tabularx}{\textwidth}{lX}
\toprule
\textbf{Value} & \textbf{Behavior} \\
\midrule
unset / \texttt{true} & All MCP tools deferred; Claude searches on demand \\
\texttt{auto}        & Load upfront if tools fit in 10\,\% of context; defer the rest \\
\texttt{auto:N}      & Threshold mode with custom percentage \texttt{N} (0--100) \\
\texttt{false}       & Load all MCP tools upfront — the pre-Tool-Search behavior \\
\bottomrule
\end{tabularx}
\end{table}

To exempt a specific server from deferral (its tools should always be
loaded), set \texttt{alwaysLoad: true} in that server's entry in
\texttt{.mcp.json}.

\begin{notebox}
Tool Search requires a model that supports \texttt{tool\_reference} blocks:
Sonnet 4 / Opus 4 and later. Haiku models do \emph{not} support Tool
Search and ignore the deferral.
\end{notebox}

\section{Output Limits}
\label{sec:mcp-output}

\index{MCP!output limits}

Claude Code shows a warning when an MCP tool's output exceeds
\textbf{10,000 tokens} and caps the per-tool result at \textbf{25,000
tokens} by default. Increase the cap with the
\texttt{MAX\_MCP\_OUTPUT\_TOKENS} environment variable:

\begin{lstlisting}[language=bash,caption={Raising the MCP output limit}]
export MAX_MCP_OUTPUT_TOKENS=50000
claude
\end{lstlisting}

For tools that intrinsically return large payloads (database schemas, file
trees), the server author can annotate the tool with
\texttt{\_meta["anthropic/maxResultSizeChars"]} up to 500\,000 characters.
This persists results to disk and replaces them with a file reference,
sparing your context.

\section{Connectors from claude.ai}
\label{sec:claudeai-connectors}

\index{MCP!claude.ai connectors}

If you log into Claude Code with a Claude.ai account, MCP servers
configured at
\url{https://claude.ai/customize/connectors} are automatically available in
Claude Code. They show in \texttt{/mcp} with an indicator that they came
from claude.ai. To disable them, set
\texttt{ENABLE\_CLAUDEAI\_MCP\_SERVERS=false} in your environment.

A server you configure directly in Claude Code (any scope) takes precedence
over a claude.ai connector that points at the same URL.

\section{Best Practices}
\label{sec:mcp-best-practices}

\index{MCP!best practices}

\begin{itemize}
  \item \textbf{Prefer HTTP servers over stdio} for anything that has a hosted
        endpoint — they reconnect automatically and require no local process
        management.
  \item \textbf{Use project scope (\texttt{.mcp.json}) for team servers.}
        Commit it alongside the rest of your project configuration. Keep
        secrets out via environment variable references.
  \item \textbf{Verify trust before connecting.} Servers that fetch external
        content can expose you to prompt-injection attacks.
  \item \textbf{Use the Anthropic Directory} (\url{https://claude.ai/directory})
        as your primary discovery source — servers there have been reviewed.
  \item \textbf{Leave Tool Search on} when you have more than a couple of
        servers; only set \texttt{ENABLE\_TOOL\_SEARCH=false} if you need
        the older upfront-load behavior.
  \item \textbf{Set appropriate output limits.} If an MCP tool returns large
        results, set \texttt{MAX\_MCP\_OUTPUT\_TOKENS} or annotate individual
        tools with \texttt{anthropic/maxResultSizeChars}.
\end{itemize}

\section{Exercises}
\label{sec:mcp-exercises}

\begin{exercisebox}[Exercises — connect your project to a real MCP server]
These exercises continue the running project from \cref{ch:plugin-ecosystem}.
You should have a \texttt{.claude/} directory under version control.

\begin{enumerate}
  \item Install the GitHub MCP server at \textbf{project scope}, using
        the HTTP transport. Verify with \texttt{claude mcp list} that
        \texttt{github} appears with scope \texttt{project}.
\begin{verbatim}
claude mcp add --transport http github \
  https://api.githubcopilot.com/mcp/ \
  --scope project
\end{verbatim}
  \item Open the resulting \texttt{.mcp.json} at the project root.
        Confirm the URL is stored literally but \emph{no} GitHub PAT is
        in the file. Add the file to git and commit it.
  \item Open a Claude Code session and run \texttt{/mcp}. Complete the
        OAuth flow when prompted. The panel should then show
        \texttt{github} with a non-zero tool count.
  \item Ask Claude, in plain language:
        ``List the five most recent open issues in this repository.''
        Confirm Claude calls a GitHub MCP tool rather than asking you
        for a browser URL or guessing.
  \item As a safety check, run
        \texttt{git diff -- .mcp.json} and confirm there are no secrets
        in the file you are about to push.
\end{enumerate}
\end{exercisebox}

\begin{summarybox}
\begin{itemize}
  \item MCP (Model Context Protocol) is Anthropic's open standard for
        connecting Claude Code to external tools via JSON-RPC 2.0. The
        recommended transport is \textbf{HTTP} (streamable-http); SSE is
        deprecated.
  \item Servers are added with \texttt{claude mcp add --transport http <name>

        \texttt{\textasciitilde/.claude.json}), \textbf{project}

        \texttt{\$\{VAR\}} expansion.
  \item Browse and install vetted servers from the Anthropic Directory
        (\url{https://claude.ai/directory}). Use
        \texttt{/mcp-server-dev:build-mcp-server} to scaffold a custom server.
  \item Remote servers support OAuth 2.0 authentication; run \texttt{/mcp}
        inside a session to complete the browser flow.
\end{itemize}
\end{summarybox}
